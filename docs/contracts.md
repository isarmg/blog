# 数据与请求约定

本页描述服务端、浏览器及离线工具共同遵守的约定。日常操作见[内容管理](usage.md)，实例布局见[配置参考](configuration.md)。

## 内容与身份

站点包含文章、随笔、分类标签、搜索、友链、相册、家庭、信笺、祝福板、匿名评论和留言。唯一管理员负责后台管理；访客以匿名身份参与互动，无需注册。

受密码保护的文章可出现在公开列表，也可按标题搜到，但公开搜索不匹配其正文，列表不返回正文摘要。直接读取这类文章的正文返回 `404`；通过 `POST /api/v1/articles/{id}/unlock` 验证密码后，该次响应返回正文。只有公开、无密码且允许评论的文章可以发表新评论。回复目标必须属于同一内容及评论类型，客户端不能自行指定作者身份。

所有日期输入、显示和日志日界统一为 UTC。没有时区的数据库时间和日期输入也按 UTC 解释，一天固定为 24 小时。文章进展只接受有效的绝对日期或日期时间；带偏移的时间规范化为 UTC。新建进展时，时间缺失、为 `null` 或空白值均使用创建时刻；编辑进展时，这些值保留原时间。

## 重试与幂等

文章评论（`POST /api/v1/comments`）、留言板评论（`POST /api/v1/message-comments`）和祝福板评论（`POST /api/v1/love-comments`）要求 JSON 中包含小写 UUIDv4 的 `request_id`。收据与评论在同一事务中保存，标识绑定内容、目标和父评论。重试时若目标仍允许评论，使用同一标识和内容会返回已有记录，不会再插入；改变内容或重试已删除的评论会返回 `409 Conflict`。

同一留言板上的**弹幕**是另一种写入：`POST /api/v1/tree-hole/guest` 接受去掉首尾空白后 1 至 60 个字符的 `message`，不接受 `request_id` 或图片，不提供去重。响应丢失时先刷新弹幕列表，不要自动重发。

新建文章、随笔和文章“最新进展”的请求可通过 `Idempotency-Key` 携带提交标识，浏览器为这些操作生成并保留标识。键须为 1–128 个可打印非空白 ASCII 字符；不带键的请求不提供提交去重。文章键绑定完整提交内容，随笔键绑定正文、图片和可见性，进展键绑定文章、正文和时间，收据与业务内容在同一事务中保存。未确认的提交保留原键和原始载荷；期间的新草稿单独保留，确认原提交后再修改对应记录。首次明确拒绝或确认成功后，有意再次发布使用新键。不同内容复用键，或原内容已经删除时，返回 `409 Conflict`。

页面显示“尚未确认”时，应先确认原提交，避免为同一操作生成新标识。HTTP 请求的 `X-Request-ID` 用于关联日志和错误，与上述持久化提交标识分别使用。

## 容量与错误

公开内容路由的 POST（含文章解锁、匿名评论和弹幕）共用 4 个执行名额和 32 个等候名额。排满或等待超过 10 秒返回 `503 Service Unavailable`。名额覆盖整个请求处理，不只是读取正文。文章密码计算另有 2 个并发名额，在阻塞任务中执行并在计算结束后释放；管理员登录不走这组公开内容名额。

内容接口的 JSON 请求体必须在开始读取后的 10 秒内完整接收；持续缓慢发送不会延长此期限。超时返回 `408 Request Timeout` 并关闭 HTTP 连接，不进入业务处理，同时释放写入容量。该期限只约束输入读取，不中断已开始的事务提交。

公开写入的容量控制不使用访客 IP、账号候选字符串或代理头作为计数身份。认证、同源检查、CSRF 和内容权限仍在各自的请求边界执行。

## 站点媒体

公开站点信息和后台站点设置均返回 `media` 对象，包含下表全部字段；没有配置的值为 `null`。后台保存时必须提交 `media`，且为整体替换：对象内省略的字段按 `null` 保存。因此传 `"media": {}` 会清空这组外观媒体，不表示保留旧值。

| 字段 | 展示位置 |
| --- | --- |
| `logo` | 站点标志 |
| `journey_background` | 时间轴背景 |
| `journal_background` | 随笔背景 |
| `guestbook_background` | 留言板背景 |
| `love_letter_background` | 恋爱笔记信笺背景 |
| `love_moments_cover` | 恋爱笔记“点点滴滴”栏目封面 |
| `love_photos_cover` | 恋爱笔记“时光相册”栏目封面 |
| `love_wishes_cover` | 恋爱笔记祝福栏目封面 |
| `toolbox_background` | 百宝箱横幅背景及视频封面 |
| `toolbox_video` | 百宝箱横幅视频 |

`background_image`、`avatar` 和 `random_cover` 继续分别表示首页背景、站长头像和随机文章封面；家庭资料的 `bg_cover` 表示“家”页背景。空白媒体地址保存为 `null`，清空配置不会恢复内置图片或视频。媒体地址只接受 HTTP(S) 或站点根路径，拒绝其它协议、协议相对地址和控制字符。

管理员图片上传入口为 `POST /api/v1/content/upload`，支持 PNG、JPEG、GIF、WebP，最大 10 MiB；视频上传入口为 `POST /api/v1/content/upload-video`，接受含视频轨道的 MP4、WebM，最大 50 MiB。请求体是文件原始字节，不是 JSON 或 multipart 表单；服务端按实际文件内容判断类型，用 SHA-256 命名，文件扩展名与请求 MIME 不能替代格式检查。本地资源被数据库中未删除的文章、站点外观或其它受检字段引用时，删除返回 `409 Conflict`。仅在浏览器中编辑、尚未保存的草稿不在检查范围；匿名评论与树洞消息中的纯文本提及也不阻止删除。

内容寻址的 `/media/<摘要>.<扩展名>` 成功响应使用 `Cache-Control: public, max-age=31536000, immutable`，包括 HEAD、范围请求和条件请求。删除文件后，源站返回 404，但浏览器或代理中已经缓存的副本仍可在有效期内使用；媒体删除不提供缓存撤回。

文章顶部视频保存在 `video_url`，正文视频保存在 `article_content` 的独立 `video` fenced code block 中，每块一个 URL。两者共用 Rust 视频解析器：视频文件仅接受 HTTP(S) 或站点根路径的 MP4/WebM 地址；平台地址仅接受已知 B 站、YouTube 主机与有效视频标识，生成固定 HTTPS 播放器地址，不透传任意嵌入参数。原始 HTML 一律转义；不支持的视频代码块保持为代码。服务端的媒体引用检查同时识别视频块中的浏览器规范化路径，已保存但不公开的内容同样参与引用检查。

## 数据库与离线操作

数据库身份为 `blog-db-v5`，结构修订号为 `5`。新实例按当前结构初始化。程序校验 `product_metadata`、全部 SQL 对象及当前结构摘要；结构不匹配时拒绝打开，不执行旧格式迁移。服务启动只打开已初始化的实例。新数据库由显式 `blog-setup initialize` 创建，已有数据库不会被覆盖初始化。

服务与 `blog-setup` 共用实例锁。离线检查先创建 `ROOT/run` 下的受限临时快照，在快照上验证数据库结构、内容和凭据，不改写源数据库。密码重置使用事务更新管理员凭据并撤销会话。具体命令见[运行与排障](operations.md)。
